
A) topic : scenes & nodes

- scenes are stored with unique hashed keys in the datamodel as they are 
fetched by scene name from the datamodel. This means that there can only be
one scene with any particular name.

This is okay because of these conditions:
    - scenes can only be parented to the datamodel directly
    - scenes are able to dynamically be created / destroyed at runtime
    and such scene IDs are more difficult to manage than scene names

- with nodes, a node can be parented to any scene, and a node can be parented
to any node.
- nodes are searched for via traversal of the scene tree (at render time) 
rather than by name
- nodes *should* be wrapped in lifetime managed structs rather than freely
existing.
